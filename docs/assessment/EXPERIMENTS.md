# Experiment register and improvement ledger

Authoritative register: [`experiments.json`](experiments.json). Each experiment's hypothesis, success criteria and rejection criteria are written there **before** it is run. This page is generated by `server/test/batch/ledger.ts` from the stored run scores, so its figures are not typed by hand. Run data and documents stay in the git-ignored `server/data/evaluations/`; only aggregates are committed, in `batches/<batch>/results.json`.

**Decisions:** demonstrated improvement within the evaluated scope / correctness fix with no measured broader gain / inconclusive / regression / rejected. Passing these checks supports a scoped claim, not a guarantee.

### M1: Measurement correction: the scorer, not the system

* **Date:** 2026-10-28. **Component:** evaluation. **Failure class:** two scorer defects
* **Hypothesis:** (a) The scorer expected certifications in a separate list, but the schema files them as education entries of type certificate. (b) Passing checks carried no expected value, so a comparison could not match a check that changed between right and wrong; earlier "0 regressions" counts were not a valid test.
* **Success criteria (fixed before the run):** Every run re-scored with the corrected scorer before any verdict; comparisons refuse scores without stable check ids.
* **Rejected if:** n/a (measurement only; no system output changed)
* **Regression protection:** compare.ts refuses scores without stable check ids
* **Runs compared on the same inputs:** baseline-1 → e1-r1
* **Comparisons:** none (measurement change only)
* **Resource cost:** none
* **Examples:** certification found: 234 of 287 under education; issuer read 0 of 234
* **Decision:** **Correctness fix (measurement)**. All verdicts below were recomputed after it.

### E1: Names printed over two or three lines

* **Date:** 2026-10-28. **Component:** parser (identity). **Failure class:** IDENTITY_UNRESOLVED refusals: 48 of 300 CV documents refused (6 Word, 10 PDF, 11 scan, 21 photo), so the applicant would never appear in the list
* **Hypothesis:** Designs that print the first name over the surname, or an oversized surname first, defeat the one-line name rule; joining consecutive single-word lines confirmed by the e-mail's local part recovers them without turning headings into names.
* **Success criteria (fixed before the run):** Fewer CV refusals on the protected split; every newly published name correct.
* **Rejected if:** any new wrong name; any check from right to wrong in any format; unexplained golden-output change
* **Regression protection:** test/parser-split-names.test.ts (3 failed before; 2 counterexamples and 1 unchanged case)
* **Runs compared on the same inputs:** baseline-1 → e1-r1
* **baseline-1 → e1-r1, protected (splits.json; comparator 2.0.0):** {"refused → published":7,"added correct":169,"added error":103}; worsenings 103
* **baseline-1 → e1-r1, development (splits.json; comparator 2.0.0):** {"refused → published":14,"added correct":408,"added error":144}; worsenings 144
* **Superseded measurement:** "no check from right to wrong" was first computed with comparator 1.0.0/1.1.0. Re-computed with 2.0.0: 0 right → wrong, 0 correct checks removed; 7 documents refused → published, adding 169 correct and 103 erroneous checks of their own (the published documents' remaining field errors).
* **Resource cost:** no measurable runtime change (median per document unchanged; same OCR)
* **Examples:** CV0507 "Tumelo / DAVIDS" → Tumelo Davids; CV0517 "Smith / Jessica" with jessicasmith.517@… → Jessica Smith (development examples)
* **Decision:** **Demonstrated improvement within the evaluated scope** (decided by: assistant, within the evaluated scope (production promotion is the owner's)). Protected: CV documents published 112 → 119 of 135, all 7 with the right name; wrong names unchanged at 3. Remaining protected refusals: 16 (10 of them photos). Reproduced exactly from the clean commit (e1-r1 against the earlier uncommitted run: no difference).

### E2: " / " separates skill-list items

* **Date:** 2026-10-28. **Component:** parser (skills). **Failure class:** skill recall 64 of 376 (Word) at baseline: slash-separated skill lists were judged to be prose and dropped; the few skills shown came from a dictionary fallback, which also renamed them
* **Hypothesis:** Treating a spaced slash as a list separator (and keeping a slash inside a name such as CI/CD) recovers listed skills.
* **Success criteria (fixed before the run):** Higher skill recall on the protected split; printed-skill precision not more than 2 points lower; unsupported skill names not increased; no check from right to wrong.
* **Rejected if:** any of: precision down more than 2 points; unsupported skill names up; any right-to-wrong check; unexplained golden-output change
* **Regression protection:** test/parser-slash-skills.test.ts (3 failed before; counterexample: CI/CD, TCP/IP and UI/UX read exactly as in a comma list)
* **Runs compared on the same inputs:** e1-r1 → e2-r1
* **a-default-r1 → b-e2-r2, validation (splits-v2.json; comparator 2.0.0):** {"wrong → right":263,"removed error":8,"added correct":263}; worsenings 0
* **a-default-r1 → b-e2-r2, development (splits-v2.json; comparator 2.0.0):** {"wrong → right":982,"added correct":982,"removed error":117,"added error":65}; worsenings 65
* **a-default-r1 → b-e2-r2, protected (splits.json; comparator 2.0.0):** {"wrong → right":579,"removed error":42,"added correct":579,"added error":35}; worsenings 35
* **Downstream matching:** no new unjustified credit at leaf level in any format; under-credit against verified inputs recovered: Word and text 669 each, PDF 563, scan 515, photo 327 (matching-a-default-r1_b-e2-r2_c-e3-r1.json)

### E3: Admission check for skill-list pieces (on top of E2)

* **Date:** 2026-10-28. **Component:** parser–reading interface: admission of list pieces. **Failure class:** E2 admits every " / " piece as a skill. On OCR'd photos and scans, column interleaving puts prose and fragments from another column into the skills block ("Recent responsibilities include tracking", "am", "and", "improvement"), and wrapped items arrive split ("Root cause" / "analysis").
* **Hypothesis:** Most E2 false positives are list pieces that are not complete items: they begin or end with a function word, or come from the far side of a column boundary (" | " inside a " / " list) and are prose-like. Refusing those pieces keeps E2's recall.
* **Success criteria (fixed before the run):** Measured A (accepted default 2.9.0), B (E2), C (E2+E3) on the same inputs, on the validation split v2 (13 candidates) and on development v2 separately, per format AND in total: unsupported skill names in C ≤ A in every format and in total (E2's original gate, unchanged); C's skill-recall gain over A ≥ 90% of B's gain in every format; extra-printed skill errors C ≤ B in every format; no right → wrong check outside skills against A; median runtime per format ≤ B + 10%; golden outputs unchanged.
* **Rejected if:** any success condition not met. Validation v2 is not fresh: even a pass permits no promotion; promotion evaluation is blocked until a new batch.
* **Regression protection:** test/parser-list-admission.test.ts (written before the change)
* **Runs compared on the same inputs:** a-default-r1 → c-e3-r1
* **a-default-r1 → c-e3-r1, validation (splits-v2.json; comparator 2.0.0):** {"wrong → right":263,"removed error":8,"added correct":263}; worsenings 0
* **b-e2-r2 → c-e3-r1, validation (splits-v2.json; comparator 2.0.0):** {}; worsenings 0
* **a-default-r1 → c-e3-r1, development (splits-v2.json; comparator 2.0.0):** {"wrong → right":987,"added correct":987,"removed error":127,"added error":67}; worsenings 67
* **b-e2-r2 → c-e3-r1, development (splits-v2.json; comparator 2.0.0):** {"right → wrong":2,"removed correct":2,"wrong → right":7,"added error":3,"added correct":7,"removed error":11}; worsenings 7
* **Downstream matching:** matching-a-default-r1_b-e2-r2_c-e3-r1.json: no new unjustified credit in any format; 33 more under-credited criterion leaves recovered on photos
* **Resource cost:** median per document unchanged or lower than B (photo 2,400 → 2,245 ms on development); no downloads; three batch runs
* **Examples:** development CV0503 (PDF, scan): "Attention to detail" lost because the filtered line became prose; CV0522 scan: "Data day delivery" admitted; CV0530 photo: "Supplier coordination coordination" admitted, alongside six real skills recovered

### Unresolved after this batch

* Job titles under a decorative folio line: 13 of 180 job documents refused (TITLE_UNRESOLVED).
* Job employer read as the e-mail address (employer correct 18 of 107 Word and PDF jobs) and job location missing from text files (0 of 60).
* Application-information lines leaking into requirements (desirable requirement precision 316 of 1,174 at baseline).

* OCR fragments in skill names on photos (E5, reading layer).
* Matching measured only as propagation against verified inputs with a rules assessor (rules-batch-0.1.0); assessor correctness unmeasured (no independent criterion labels).
* Review-budget tie rule: verified review sets exceed twice the budget in 43 of 60 jobs (owner policy decision).
* Reading order on PDF, scan and photo produces unjustified credit downstream (205, 320, 481 leaves) and E2's fragments: next experiment E4.

* **Linked:** R24, R27, R29
* **Symptom:** 12 concurrent uploads: ~14 s warm at baseline, 15-16 s after; 4 s unrelated-request gate failing at a pool of 3
* **Hypothesis:** H1: wall time scales with database statements per document through a small connection pool; reservation and release added ~2 of ~14

* **Decision:** accepted the change; gate retained unchanged and failing at a pool of 3; residual unexplained; H3 untested

## Model-layer experiments (evidence assessment)

### EA1 (2026-10-28)

* **Hypothesis:** A pretrained local instruct model applying the written rubric to the same passages assesses requirement leaves more accurately than the rules baseline on negation, wishes, contradictions, title-only roles, weak use and transfer gating, without more unsupported positive assessments.
* **Baseline / candidates:** A: rules-evidence-0.1.0 (src/assessment/evidence/rulesAssessor.ts); B: qwen3:4b-instruct-2507-q4_K_M (installed, Apache-2.0, 2.5 GB, Ollama 0.35.1, temperature 0, seed 0); B8: qwen3:8b (installed, Apache-2.0, 5.2 GB): the ONLY changed factor is the model; prompt and rubric identical
* **Data:** server/test/assessment/evidence/annotations-v0.1.jsonl (47 items, 11 categories; sha256 5d6d348a9c1fa0e9…); evaluation split 21 items reserved by stratified hash before any model run; development 26. Labels: proposed by the assistant, NOT independent; every result is provisional until a person reviews the labels
* **Acceptance (pre-registered):** On the evaluation split, for B to count as better than A WITHIN THIS SET: unsupported positives B ≤ A; state agreement B ≥ A + 3 items; repeatability 100% identical states; validator refusals ≤ 10% of items; maximum latency ≤ 10 s per leaf. Passing supports only a provisional, unreviewed-label claim: no promotion, no integration.
* **Run ea1-r1:** INVALID (integration defect, not a model result): the runtime schema offered abstain as a nullable enum and the constrained decoder never chose null, so both models' states were overridden as abstentions (8B abstained on 46 of 47 items); the 4B model's long rationales failed the 400-character schema check (26 refusals). Diagnosed on a development item only. Rules baseline unaffected: evaluation agreement 14 of 21.
* **Run ea1-r2:** valid run
* **Results:** Evaluation split, 21 items, labels unreviewed. A rules: 14 of 21 states agree; 5 unsupported positives (two negations and one wish credited as named; a contradiction credited as named; a title-only role counted relevant); 2 missed; 6 consequential. B qwen3 4B: 15 of 21; 1 unsupported positive ("reconciled customer accounts" read as customer service); 2 missed (abstained on a clear negation; abstained on a wish next to shown use); 2 consequential; 21 of 21 repeatable; 0 refusals; 4.6 s median and 5.7 s maximum per leaf. B8 qwen3 8B: 11 of 21; 1 unsupported positive; 7 missed (named, course, transfer and described evidence answered as no evidence); 6 consequential; maximum 10.8 s per leaf.
* **Decision:** **Failed its pre-registered agreement gate against unreviewed proposed labels; not eligible for promotion** (decided by: assistant, against the pre-registered gates (the owner may overrule)). B needed at least 3 more agreeing states than the rules on the evaluation split and achieved 1 more; B8 failed agreement and latency. Not reinterpreted. Reduced false credit (1 unsupported positive against 5; 2 consequential against 6) is a promising exploratory finding, not independently verified improvement. No training, no prompt tuning.
