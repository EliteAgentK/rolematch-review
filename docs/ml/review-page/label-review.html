Annotation guide

The rule that matters most

Judge the exact requirement, with its scope. Mentioning the tool does not earn credit for a more specific responsibility: "Tableau" in a skills list is not "Tableau dashboard development".

Distinctions

Tableau viewing versus development. Viewing or using reports someone else built is exposure to the tool. Only building dashboards meets "dashboard development".

Kubernetes deployment versus administration. Deploying applications to a cluster is not administering the cluster. It neither proves nor rules out administration.

No production experience versus no experience. "Not used in production" limits the claim; it does not say the person has never used it.

Qualification mentioned versus completed. A listed qualification, or dates of study, does not prove it was completed. Use the stated status.

Fixture mappings versus approved policy. The transfer mappings in these examples (VBA → Python, Power BI → Tableau) are hypothetical fixtures for testing. They are not approved RoleMatch policy.

No evidence. "No evidence" means the supplied passages do not support the requirement. It is never proof that the person lacks it.

Your options

Right: the proposed answer is correct. Wrong: choose the correct answer, or leave it unresolved for adjudication. Unclear rubric: the rubric does not decide this case. A note is welcome on any choice.
