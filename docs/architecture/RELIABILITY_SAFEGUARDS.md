## Enterprise single sign-on and stronger administrator authentication: where they fit
* **Boundary:** identity is Supabase Auth; RoleMatch only trusts the session it issues and maps `auth.users.id` to `members`. SSO therefore belongs at the identity layer: SAML/OIDC providers configured per organisation in Supabase Auth, with the callback landing in the same session code. Nothing in portals, capacity or invitations needs to change, because they key on the user id and the verified e-mail.
* **Must be decided first:** whether an organisation may require SSO-only sign-in (disabling password login for its domain), how an invited address is bound to the identity provider's verified e-mail, and just-in-time membership rules (an SSO user must still hold an invitation; no automatic portal access).
* **Stronger administrator authentication:** require MFA (TOTP) for organisation administrators and for sensitive actions (delegating portal creation, removing administrators). Supabase Auth supports TOTP; the work is an "AAL2 required" check on those routes and enrolment screens.
* **Effort (uncertain):** MFA for administrators about 3-4 days; SAML/OIDC for one pilot client about 1-2 weeks including the first client's identity-provider setup, plus plan/entitlement work on Supabase (a paid feature). No connector has been added.
